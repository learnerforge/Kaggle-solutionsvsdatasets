The optimization ladder (R7)

When a cycle misses the gate, the feedback sent back to the coder is ordered by this ladder — evidence before capacity, measurement before modelling:

  1. 1. Clean leak-free baseline
    A measured, boring solution that runs top-to-bottom.
  2. 2. Sanity-check folds and metric
    Fold variance, worst fold, metric implementation bugs.
  3. 3. Domain feature engineering
    From the problem statement — not from a feature list on the internet.
  4. 4. Model zoo
    LightGBM + XGBoost + CatBoost, each measured separately on OOF.
  5. 5. OOF-fitted ensemble
    Rank-mean for rank metrics; hill-climb weights otherwise — never fitted on test predictions.
  6. 6. Fold-safe target encoding
    High-cardinality columns, encoded excluding each row's own fold.
  7. 7. Pseudo-labelling
    Confident test rows, validated honestly on OOF.
  8. 8. Bounded hyperparameter search
    Fixed seed budget, only after steps 1–4 are clean and measured.

Security & operations

Kaggle credentials are resolved from environment variables or ~/.kaggle/kaggle.json — never from a shared database, never printed, never committed. If a Vercel database is attached later, it stores the dashboard projection only; credentials stay in Vercel Environment Variables and are served through a dedicated endpoint that the engine reads only when explicitly configured. Datasets and training artifacts are git-ignored by construction (R12), and the legacy NTG/ folder is never read or written by the engine (R10).
